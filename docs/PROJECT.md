# Project scope

Status: 0.1.0 preview, 2026-11-01. Behavior reference: Stepsy 1.6.2 FOSS, repository commit `2ff512d34dcd858688e64a83f6c2fc1d778f75f6`.

## Product

Provide the same useful walking records and controls as Stepsy on a Linux phone, as an independent implementation. Preserve feature semantics and data portability while adapting interaction to GNOME and Phosh. Pixel-identical Android layouts are not the target. Departures from reference behavior are documented below.

Target hardware: FuriPhone FLX1s, arm64, FuriOS, Phosh. Other phones and distributions are unverified.

| Milestones and achievements | Implemented |
| Charts and history | Implemented |
| Distance and calories | Implemented as labelled estimates, metric and imperial |
| Manual and timed pause | Implemented |

| CSV export and import | Implemented, with a preview before replacing history. Stepsy CSV and database files are accepted |
| Automatic backups | Implemented, with a chosen folder, interval and retention |
| Preferences and appearance | Implemented. English, German and Russian |
| Widgets and quick settings tile | Not implemented. A Phosh extension needs separate research |
| Broadcast automation controls | Not implemented. The recorder's D-Bus interface is internal |

The proprietary activity-recognition option in the reference's Full edition has no Linux equivalent, and vehicle or cycling filtering is not claimed.

## Deliberate differences from the reference

- Goals and streaks use the goal in force on each day, so changing a goal does not rewrite past days.
- Steps accumulated across midnight count for the day they are received. Closed days do not change.

## Architecture

- `pace-recorder` holds the SensorFW session: control over D-Bus, samples over a framed Unix socket. It persists totals and the counter baseline in one SQLite transaction, every 60 seconds and before each boundary such as midnight, a pause or an edit. A crash between writes loses no steps the sensor has already counted, because the baseline lags together with the total. The sensor does not count without an active session, so steps walked while the recorder or SensorFW is down are lost.
- `pace-ui` reads the database and talks to the recorder over the session bus. Closing it does not stop counting.
- `pace-core` holds the logic without any user interface or D-Bus dependency.
- No runtime Internet access, location tracking, accounts, advertising or telemetry.

## Packaging

Native arm64 Debian package, with shared-library dependencies generated by `dpkg-shlibdeps`. The recorder is enabled for all users through `/usr/lib/systemd/user/default.target.wants`; the maintainer scripts start it after installation, restart it on upgrade and stop it on removal. Flatpak is not planned yet: SensorFW bus and socket access and the recorder's lifetime would need deliberate integration.

## Release criteria

No production claims before measured walking accuracy, screen-off and suspend behavior, recovery from service loss, battery overhead, transactional restore, locale and date handling and package rollback are demonstrated. Record test revision, device OS, conditions, expected result and actual result. A running process or a successful build alone is not evidence that walking was counted correctly.
